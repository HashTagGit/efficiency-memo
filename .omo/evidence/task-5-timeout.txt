3. Test 2 — Postgres unreachable (the spec's "60s timeout" case)
----------------------------------------------------------------
  $ env -i PATH="/usr/bin:/bin" \
        POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=19999 \
        POSTGRES_DB=postgres POSTGRES_USER=postgres POSTGRES_PASSWORD=test \
        timeout 70 bash scripts/init-supabase.sh
  Waiting for Postgres at 127.0.0.1:19999 (db=postgres)...
  ... <loop runs ~60 times> ...
  ERROR: Postgres not ready after 60s at 127.0.0.1:19999
  exit_code=1

  Result: PASS — the script:
          - reaches the wait loop (env-var guard did not block)
          - times out after 60 seconds
          - prints the spec'd error to stderr
          - exits 1

  Note on output noise: the Windows host does NOT have `pg_isready` on PATH
  (it ships in the postgres:17-alpine container where the init script is
  meant to run), so the 60 loop iterations each print
    scripts/init-supabase.sh: line 59: pg_isready: command not found
  This is purely a Windows-host artifact. Inside the Docker container,
  pg_isready IS on PATH, returns a non-zero exit code (refused / no
  response) each iteration, and the loop behaves the same way: 60
  attempts, then the timeout error and exit 1.
