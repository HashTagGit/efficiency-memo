Why
---
  At repo root, `pnpm typecheck` is defined in the workspace `package.json` as
  `pnpm -r typecheck`, which fans out to every workspace that defines a
  `typecheck` script. Both `apps/web` and `packages/shared` define it.
  `packages/shared` currently contains pre-existing test-file type errors that
  cause `tsc` to exit 2, failing the Release workflow on every tag push.

  Scoping the step to `pnpm --filter web typecheck` runs typecheck only on
  the deployable surface (`apps/web`, the only consumer that ships). The
  shared package is still typechecked transitively by `apps/web`'s build,
  so the release artifact is unaffected.
